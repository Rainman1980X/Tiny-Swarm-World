= ADR: Test-Only Credential Override on Dedicated Hyper-V System

*Date:* 2026-09-11
*Status:* Accepted; restricted exception for the dedicated non-production test system
*Decision makers:* Tiny Swarm World architecture and security governance

== Context

The live end-to-end and WSL evidence tests require deterministic bootstrap
credentials on a dedicated Hyper-V test system. The system is used only for
disposable development and acceptance testing and is never a production
runtime. The existing safety contract correctly prohibits committing real
credentials and prohibits treating a local test result as production or live
acceptance evidence.

The test harness nevertheless needs a repeatable, non-interactive override for
the test system. Without an explicit decision, an operator could either copy
credentials into an unsafe location or silently weaken the general credential
handling policy.

== Decision

An exception is accepted for a credential-override script used solely against
the dedicated Hyper-V test system.

The exception is bounded by all of the following rules:

* The target is a disposable, non-production test system and must never serve
  production traffic or hold production data.
* The override may contain only dedicated test credentials. Production,
  customer, shared-operations, or personal credentials are forbidden.
* The override must be used only for the explicitly identified test target and
  must not become a default installer or runtime configuration.
* The script must create the remote environment file with owner-only
  permissions and must not print credential values into logs or evidence.
* The credentials must be rotated or invalidated when the test system is
  rebuilt, transferred, exposed outside the test network, or retired.
* The script is test plumbing, not acceptance evidence. Its presence and a
  successful local run do not establish production readiness, public-beta
  readiness, or a live green-path result.
* The override must not bypass explicit live-consent, reset-confirmation,
  host-boundary, or redaction controls.
* Removing the dedicated test-system boundary, using the script for a second
  target, or introducing production-like data requires a new security review
  and a superseding ADR.

== Consequences

The test workflow can run deterministically through the dedicated Hyper-V
environment without interactive credential entry. The repository accepts a
narrow test-only risk that would otherwise be unacceptable for production
configuration.

The exception increases the impact of accidental script disclosure, so access
to the test repository, test host, and test network must remain restricted.
Reviewers must reject any reuse of the override outside the stated target or
with credentials that are not disposable. Test results must continue to record
their environment and verification state without recording secrets.

== Considered Options

=== Commit production or shared credentials

Rejected because disclosure would affect systems or identities outside the
disposable test boundary.

=== Infer credentials from the execution environment

Rejected because implicit credentials make the test non-reproducible and hide
the authorization boundary.

=== Require interactive credential entry for every test

Rejected for this narrowly scoped non-interactive acceptance harness, while
remaining the preferred approach for production and shared environments.

=== Keep the override out of version control

Preferred for production and shared environments. Not selected for this
dedicated test-system exception because the test workflow requires a reviewed,
repeatable harness and the credentials are disposable test-only values.
