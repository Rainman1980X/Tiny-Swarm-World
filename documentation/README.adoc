|===

| `arc42.adoc` | Canonical architecture book assembled from `documentation/arc42`.

| `qms/` | QMS-light quality objectives, CAPA, change-control and internal-audit guidance.
| `governance/` | Branch protection, CI quality-gate and pull-request review policy.
| `deployment/` | Legacy deployment workspace. Current deployment system references live under `arc42/07_deployment/`; Infisical setup configuration lives under `arc42/08_deployment_configuration/`.
| `configuration/` | Legacy configuration workspace. Current operator configuration contracts live under `arc42/08_configuration/`.
| `architecture/` | Legacy architecture workspace. Current ADRs, analyses, and migration plans live under `arc42/`; process execution plans live under `process/`.
| `epics/` | Legacy EPIC workspace. Current introduction and requirement baselines live under `arc42/01_introduction/`.
| `process/` | Repository process, workflow, and skill/agent documentation.
| `process/agent-plans/` | Agent-oriented work split plans.
| `process/agent-tasks/` | Import-ready agent task lists.
| `workflow/` | Active and issue-scoped workflow records. Operator instructions belong in `user_guide/`.
| `process/skills/audit/` | Skill registry and ownership audit artifacts.
| `manuals/` | Audience-specific entry points that link to canonical sources.
|===

== Consolidation Rules

Use `arc42.adoc` for architecture and the three task-oriented pages in
`user_guide/` for operators. `document.adoc` assembles those same sources for
continuous reading; do not maintain a separate handbook or duplicate their
procedures in another file.
Keep detailed reference pages in their existing folders when they carry
specialized operational, ADR, or workflow evidence. Do not copy password values,
tokens, host-specific IP addresses, or generated local evidence into committed
documentation.

When behavior changes, update the nearest source page and then update the
navigation or aggregate includes that expose the behavior to readers.
